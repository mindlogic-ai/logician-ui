# Using Semantic Tokens (5.0 · BAZE)

Components and apps read **role tokens** only. The raw scales (`ink`, `sand`,
`slate`, `coral`, the 12 system hues) exist so the theme can build the roles;
reading them directly means a theme switch or a tenant override will not follow.
Values and contrast for every token: **Setup/Theme/BAZE Palette**.

## Three layers

| Layer | Names | Example |
| --- | --- | --- |
| Raw scale (colour names) | `ink.1–12`, `inkDark.1–12`, `sand.*`, `slate.*`, `coral.*`, `red.base` … | never in components |
| Semantic step (role names) | `neutral.1–12`, `secondary.1–12` | a specific neutral step no role names |
| Semantic role | `bg.*`, `layer.*`, `fg.*`, `border.*`, `primary.*`, `secondary.*`, `action.*`, `send.*`, `count.*`, `disabled.*`, `focus.ring`, status, `tooltip.*`, `category.*`, `data.*`, `diverging.*` | everything else |

```ts
createLogicianTheme()                    // BAZE: { neutral: 'ink', secondary: 'sand' }
createLogicianTheme({ neutral: 'slate' }) // cool gray — app code unchanged
<LogicianProvider theme={{ neutral: 'slate' }} />
```

## Which token

| Need | Token |
| --- | --- |
| Page background | `bg.canvas` (layer 0) |
| Sidebar / panel on the page · card on that panel · panel in a card | `layer.1` · `layer.2` · `layer.3` (each with `.hover` / `.active`) |
| Raised surface (card, menu, popover, input) | `bg.surface` |
| Body · secondary · caption text | `fg.default` · `fg.muted` · `fg.subtle` |
| Icon · placeholder | `fg.icon` · `fg.placeholder` |
| Link | `fg.link` + underline, hover `fg.linkHover` |
| Divider · card border · input/checkbox border | `border.subtle` · `border.default` · `border.control` |
| Primary (black) fill · text on it | `primary.main` / `.hover` / `.active` · `fg.onPrimary` |
| Hover / press wash, selected row | `primary.wash` / `primary.washActive` · `primary.selected` |
| Soft badge/tag fill, avatar fallback, wash card, info box · notice band · brand modal header | `bg.muted` · `bg.subtle` · `layer.3` (neutral grounds) |
| Beige accent: text, icons, borders on those (`secondary` identity) | `secondary.fg` / `.fgStrong` / `.border` |
| Beige tint (tint/accent only — **not a component background**: reads peach as a fill) | `secondary.surface` / `.surfaceStrong` |
| Run button (black + coral icon) · small coral marks | `action.bg` / `.fg` / `.iconOnSolid` · `action.mark` |
| Send button, Button `accent` | `send.bg` / `.bgHover` / `.bgActive` / `.fg` |
| Unread count | `count.bg` / `count.fg` |
| Disabled (no opacity) | `disabled.bg` / `disabled.fg` · fill-less ghost button: `disabled.fgGhost` |
| Status | `danger` · `success` · `warning` · `info` → `.bg` `.border` `.fg` `.solid` `.onSolid` |
| Decorative category (tiles, avatars, tags, charts) | `category.{hue}.surface` / `.fg` |
| Single-measure chart, usage bar, map, heatmap fill | `data.1`–`data.4` (4 = largest) |
| Chart fill above / below a real baseline (vs plan, vs average) | `diverging.pos.1–3` / `diverging.neg.1–3`, `diverging.mid` at the baseline |

Emphasis is weight, not colour: headings use `fg.default`, never `primary.*`.
Status colours mean status — don't borrow `success`/`warning` for decoration;
that is what `category.*` is for.

## Blue means data and links

Blue is the one hue BAZE gives a meaning outside status: **data and links**.
Use it for both, and for nothing decorative.

- **Links** — `fg.link` / `fg.linkHover` (blue ink, #48607A / #AFC7E1), in chat
  messages, markdown and app copy alike. Never ink-black or coral for a link.
- **Data visualisation** — usage/share bars, single-measure bar charts, maps,
  heatmaps, progress-by-share: the `data.*` ramp, a **blue monochrome ramp**,
  never a rainbow and never a grey ramp. Steps differ in lightness only (the
  saturated `blue.base` is left out). **The higher number is the larger value**:
  `data.4` is the strongest step in both modes (dark mode flips the lightness,
  so `data.4` is the lightest blue there).
- **Lines** — a single-measure line chart, and series 1 of a multi-series one,
  stroke in `blue.base` (`#4674A4` / `#6892BD`, ≥ 4.5:1). A 2px line is not a
  filled area: the ramp's darkest step `blue.ink` reads as slate grey at that
  width, so lines take the saturated blue the ramp leaves out.

| Token | Light | Dark |
| --- | --- | --- |
| `data.4` (largest) | `#48607A` (`blue.ink`) · white label | `#AFC7E1` (`blue.inkDark`) · ink label |
| `data.3` | `#7492B3` (`dataviz.blueMid`) · ink label | `#7492B3` · ink label |
| `data.2` | `#AFC7E1` (`blue.inkDark`) · ink label | `#48607A` (`blue.ink`) · white label |
| `data.1` (smallest) | `#DFEBF9` (`blue.surface`) · ink label | `#232F3D` (`blue.surfaceDark`) · white label |

Pick each label by measured contrast (≥ 4.5:1), not by step number. Ink is
`#252525`, white is `#FFFFFF`, in either mode; `contrast.test.ts` re-measures
every label in this section, including the diverging table below.

A chart that must tell several *categories* apart (multi-series lines) starts
with the same data blue (`blue.base`) and then cycles `CHART_SERIES_HUES` in
`LineGraph/seriesColors.ts` (teal, pink, indigo, purple, brown, …), which
leaves red, yellow and green out so no series reads as a status.
`info` is also blue; status always comes with an icon and words, so a blue
chart is never mistaken for an info notice.

### Diverging: above and below a baseline

When the value has a **real zero or baseline** and both directions mean
something — actual vs plan, this month vs the average, change since last
week — use the `diverging.*` ramp. A one-sided value (a count, a share, a
usage total) keeps `data.*`, even if some bars are small.

- **Blue is above the baseline, orange is below** (`diverging.pos.*` /
  `diverging.neg.*`). `3` is the largest distance from the baseline on either
  side, and the two sides share their lightness per step, so the same
  distance looks the same size in both directions.
- **The baseline itself is `diverging.mid`** (neutral step 3, so it follows
  the neutral scheme). Never white or `bg.canvas`: a "no change" cell must
  still read as a cell.
- **Never red and green for direction.** Above/below is not good/bad. When a
  direction is good or bad, that is a status: say it with an icon and words,
  as everywhere else.
- **Orange is for fills only** — bars, cells, areas. Never orange text or
  icons; labels and axis text stay `fg.*`. Lines keep the stroke rules
  above.
- **The legend names the direction in words** ("above plan" / "below plan"),
  not only with the two colours.

| Token | Light | Dark |
| --- | --- | --- |
| `diverging.pos.3` (far above) | `#2C5D91` · white label | `#A9C7EB` · ink label |
| `diverging.pos.2` | `#5890CD` · ink label | `#5890CD` · ink label |
| `diverging.pos.1` (just above) | `#A9C7EB` · ink label | `#2C5D91` · white label |
| `diverging.mid` (at the baseline) | `#EDE9E2` (`neutral.3`) · ink label | `#2E2F2F` (`neutral.3`) · white label |
| `diverging.neg.1` (just below) | `#E4BBA0` · ink label | `#85491A` · white label |
| `diverging.neg.2` | `#BF7946` · **no in-cell label**; label outside the mark | `#BF7946` · **no in-cell label**; label outside the mark |
| `diverging.neg.3` (far below) | `#85491A` · white label | `#E4BBA0` · ink label |

`diverging.neg.2` clears neither label (ink 4.41:1, white 3.48:1), so values
for that step go beside or above the bar, not inside it. The `diverging.mid`
values shown are the `ink` scheme; with `neutral: 'slate'` it is slate step 3.

The diverging ramp is a dedicated data-viz ramp (OKLCH chroma ≈ 0.10–0.11 at
steps 2–3, 0.06 at step 1, the same on both sides): paired with the dusty
`data.*` blue (≈ 0.05), any warm hue reads as brown. Blue ↔ orange
also keeps the widest colour-blind separation of the pairs considered; gold
reads as a warning and purple collapses into blue for deuteranopes.

`data.*` and `diverging.*` are fills: under high contrast they keep their
value (like `bg.track`), and in-cell labels are audited at 4.5:1 in light and
dark.

## Modes

Every role flips with the colour mode (`_light` / `_dark`) and has a
high-contrast value under `prefers-contrast: more` (text 7:1, controls/icons
4.5:1). `src/theme/contrast.test.ts` measures every registered fg/bg pair in all
four modes; adding a token without registering its pair fails CI.

## Migrating from 4.x

4.x names still resolve in 5.0 as deprecated aliases (removed in 6.0) and the
`no-deprecated-tokens` lint rule names the replacement. Run the codemod:
see `MIGRATION-5.0.md` and `codemods/5.0/README.md`.

| 4.x | 5.0 |
| --- | --- |
| `primary.lightest` / `extralight` · `lighter` · `light` · `dark` / `darker` | `primary.wash` · `primary.washActive` · `border.strong` · `fg.default` |
| `primary.fill` · `fillStrong` | `primary.main` · `primary.hover` |
| `{danger,success,warning}.lightest/extralight` · `lighter/light` · `main` · `dark/darker` | `.bg` · `.border` · `.solid` · `.fg` |
| `secondary.extralight` · `lighter` · `light` · `main` · `dark` | `secondary.surface` · `.surfaceStrong` · `.border` · `.fg` · `.fgStrong` — the first two are tint-only, not a background: a 4.x `bg="secondary.extralight"/"lighter"` becomes `bg.muted` (or `bg.subtle` for a page-level band) |
| `bg.selected` · `fg.accent` | `primary.selected` · `primary.main` (links → `fg.link`) |
| `slate.0/50 · 100 · 200 · 300 · 400 · 500/600 · 700 · 800/900 · 1000/1100 · 1200/1300 · 1400/1500` | `neutral.1 · 2 · 3 · 5 · 6 · 7 · 8 · 9 · 10 · 11 · 12` |
| raw `blue.N`, `gray.N`, `rose.N` … | removed — pick the role by use (`gray.N` follows the slate row) |

# Radio

A set of options where the user picks exactly one, all visible at once.

## When to use

- Two to five options that fit on screen, where seeing them side by side helps
  the user choose: a credit allocation mode, a visibility setting.
- Options that each need a line of explanation under the label.

## When not to use

- More than about five options, or a list that grows → `SelectField`, or
  `ComboboxField` when the user would search.
- Any number of choices, or a single yes/no → `Checkbox`. A setting that is on
  or off → `Switch`.
- Switching between views of the same content → `SegmentedControl` or `Tabs`.

# Radio

선택지를 모두 펼쳐 놓고 그중 하나만 고르게 합니다.

## 언제 쓰나요

- 화면에 다 들어가는 두세 개에서 다섯 개 정도의 선택지를 나란히 보고 고를 때: 크레딧

- 선택지가 다섯 개를 넘거나 늘어날 수 있다면 `SelectField`를, 검색이 편하다면
  `ComboboxField`를 씁니다.

  씁니다.
- 같은 내용의 보기 방식을 바꿀 때는 `SegmentedControl`이나 `Tabs`를 씁니다.

## Content

- The question above the group names what is chosen (크레딧 배분 방식).
- Options are short, parallel and mutually exclusive. Order them by likelihood
  or by size, not at random.
- If none of the options may apply, add one that says so (제한 없음) rather than
  leaving the group with no selection.

## Accessibility

What Radio does for you:

- Native radio inputs inside a `radiogroup`. Tab moves into the group onto the
  selected option; the arrow keys move and select (WCAG 2.1.1).
- Each radio emits a unique id for its control and its indicator (the
  duplicate-id defect in `ACCESSIBILITY.md` §4, KWCAG 5.4.1.1 마크업 오류 방지).
- Keyboard focus shows a ring on the control (WCAG 2.4.7); the selected state
  is a dot, not colour alone (WCAG 1.4.1).

What you still have to do:

- **Name the group.** `RadioGroup` does not render a label part, so pass
  `aria-labelledby` pointing at the visible question, or `aria-label` (WCAG
  1.3.1, 4.1.2).
- Every option needs a `Radio.Text`.
- Put a group error in words under the group (WCAG 3.3.1).

## 문구

- 묶음 위 질문에는 고르는 대상을 씁니다(크레딧 배분 방식).
- 선택지는 짧고 같은 형식으로 쓰며 서로 겹치지 않게 합니다. 아무렇게나 두지 말고
  가능성이 높은 순이나 크기순으로 둡니다.
- 어떤 선택지도 해당하지 않을 수 있다면, 아무것도 고르지 않은 채로 두지 말고 그렇다고
  말하는 선택지를 하나 둡니다(제한 없음).

## 접근성

Radio가 알아서 하는 일

- `radiogroup` 안의 네이티브 라디오 입력입니다. Tab을 누르면 묶음 안의 선택된 항목으로
  들어가고, 방향키로 옮기면서 고릅니다(WCAG 2.1.1).
- 라디오마다 컨트롤과 표시에 서로 다른 id를 씁니다(`ACCESSIBILITY.md` 4절의 중복 id
  결함, KWCAG 5.4.1.1 마크업 오류 방지).
- 키보드 초점 링이 컨트롤에 보이고(WCAG 2.4.7), 선택 상태는 색이 아니라 점으로
  나타납니다(WCAG 1.4.1).

직접 챙겨야 하는 일

- **묶음에 이름을 붙입니다.** `RadioGroup`은 라벨 부품을 그리지 않으므로, 보이는
  질문을 가리키는 `aria-labelledby`나 `aria-label`을 넘깁니다(WCAG 1.3.1, 4.1.2).
- 선택지마다 `Radio.Text`가 있어야 합니다.
- 묶음 전체의 오류는 묶음 아래에 문구로 보여 줍니다(WCAG 3.3.1).

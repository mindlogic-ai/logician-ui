# InlineCode

Code inside a sentence: a field name, a value, a shortcut. A small chip one
size below the text around it (`textStyle="subtext"`, em-relative), with a
`bg.subtle` fill and a hairline ring.

## When to use

- Identifiers the user types or will see in code or settings:
  `finish_reason`, `model_id`, a file name.

## When not to use

- More than one line → `Code`.
- A value the user only needs to copy → `CopyableCode`.
- Emphasis or warnings → plain text, bold if it must stand out.
- Keyboard keys in instructions → write them out (Ctrl + C); the chip says
  "code", not "key".

# InlineCode

문장 안의 코드입니다. 필드 이름, 값, 단축키 같은 것을 씁니다. 주변 글자보다 한 단계
작은 칩으로 그려지고(`textStyle="subtext"`, em 단위), `bg.subtle` 배경과 얇은 테두리가
있습니다.

## 언제 쓰나요

- 사용자가 직접 입력하거나 코드·설정에서 보게 될 식별자: `finish_reason`,
  `model_id`, 파일 이름.

## 언제 쓰지 않나요

- 두 줄 이상이라면 `Code`를 씁니다.
- 복사만 하면 되는 값은 `CopyableCode`를 씁니다.
- 강조나 경고에는 일반 글자를 쓰고, 꼭 눈에 띄어야 하면 굵게 씁니다.
- 안내문의 키보드 키는 글자로 씁니다(Ctrl + C). 이 칩은 '코드'라는 뜻이지 '키'라는
  뜻이 아닙니다.

## Content

- Write the identifier exactly as it appears, including case.
- Keep Korean particles outside the chip: `length`인지, not `length인지`.

## Accessibility

What InlineCode does for you:

- It renders `<code>`, so assistive technology that reports code can, and
  the chip ring keeps it visible on `bg.sunken`, where the fill alone would
  vanish.

What you still have to do:

- Nothing in the chip is read differently by most screen readers. Do not
  rely on the code styling to carry meaning (WCAG 1.3.1); the sentence must
  make sense on its own.

## 문구

- 식별자는 대소문자까지 보이는 그대로 씁니다.
- 한국어 조사는 칩 밖에 둡니다. `length인지`가 아니라 `length`인지로 씁니다.

## 접근성

InlineCode가 알아서 하는 일

- `<code>`로 그리므로 코드를 구분해 알려 주는 보조 기술은 그렇게 읽습니다. 배경만으로는
  `bg.sunken` 위에서 칩이 사라지기 때문에 테두리를 둡니다.

직접 챙겨야 하는 일

- 대부분의 화면 낭독기는 칩 안의 글자를 다르게 읽지 않습니다. 코드 모양에 뜻을 맡기지
  말고(WCAG 1.3.1), 문장만으로 뜻이 통하게 씁니다.

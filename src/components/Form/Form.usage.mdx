# Form

The layout parts every form shares: fields, sections, a scroll area and the
footer with the actions.

| Part                                      | What it does                                                                                                                                                                                           |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `FieldRow`                                | One field: label (with `description` and an `endAdornment` slot), the control, `helperText` and `error`. Wraps `FormControl`, so ids and ARIA are wired for you.                                       |
| `FieldLabel` / `FieldHelp` / `FieldError` | The pieces `FieldRow` is made of, for layouts it does not cover. `FieldError` renders nothing when empty.                                                                                              |
| `FormSection`                             | A titled group of fields with one gap (default `4`). `divider` adds a top rule; `collapsible` (with a `title`) turns it into an accordion, and `hasError` flags a collapsed section that hides errors. |
| `FormSectionHeader`                       | The section title row (`H5`, description, `titleAdornment`, `action`) on its own.                                                                                                                      |
| `FormScrollArea`                          | A full-height scrolling column, so a sticky footer pins to its bottom.                                                                                                                                 |
| `FormFooter`                              | A sticky footer for panel forms: `start` on the left, `meta` (saved time, cost) and `action` on the right.                                                                                             |
| `FormModalFooter`                         | The modal footer: optional delete on the far left, Cancel, and a primary submit with its own loading and disabled state.                                                                               |

## When to use

- Any settings panel, create or edit modal, or sidebar form. Start with
  `FieldRow` for every field and `FormSection` for every group.
- `FormFooter` in a panel that scrolls; `FormModalFooter` in a modal.

## When not to use

- A single search box or filter bar → the control on its own, with an
  `ariaLabel` or visible label.
- A confirm dialog with no fields → `Modal` with its own footer.

| `FormFooter`                              | 패널 폼의 붙박이 푸터. 왼쪽에 `start`, 오른쪽에 `meta`(저장 시각, 비용)와 `action`.                                                                                                               |
| `FormModalFooter`                         | 모달 푸터. 맨 왼쪽의 삭제(선택), 취소, 로딩과 비활성 상태를 스스로 가진 기본 제출 버튼.                                                                                                           |

## 언제 쓰나요

- 설정 패널, 만들기·수정 모달, 사이드바 폼 어디서나 씁니다. 필드마다 `FieldRow`를,

- 스크롤되는 패널에는 `FormFooter`를, 모달에는 `FormModalFooter`를 씁니다.

- 입력란 없이 확인만 받는 대화상자는 `Modal`의 푸터를 씁니다.

## Content

- Section titles are nouns (기본 정보, 동작). Field rules are on the Input and
  Select pages.
- Footer labels name the result (저장, 만들기, 그룹 삭제). The design system
  owns no copy: `cancelLabel`, `submitLabel` and `deleteLabel` come from your
  translations.
- `meta` is a fact, not an instruction: 오후 2:14에 저장됨, 10 크레딧.

## Accessibility

What these parts do for you:

- `FieldRow` associates the label, sets `aria-invalid` when `error` is set,
  and points `aria-describedby` at the helper and error text. `required`
  shows the asterisk and marks the control required.
- `FormModalFooter` keeps the submit a `type="submit"` button inside a
  `<form>`, so Enter submits; pass `onSubmit` only for a portalled or
  form-less modal. `isSubmitting` disables every button so the modal cannot be
  dismissed mid-request. Pair it with `submitLoadingText` ("Saving") so the
  busy submit button still says what it is doing.
- A collapsed `FormSection` with `hasError` swaps its chevron for a danger
  glyph, so hidden errors are not missed.

What you still have to do:

- **Name controls that `FieldRow` cannot reach.** `SelectField`,
  `ComboboxField` and `Slider` take their name from their own label part: pass
  the row's label as `ariaLabel` (`ACCESSIBILITY.md` §1).
- A flat `FormSection` and `FormSectionHeader` render the title as an `<h5>`. Check
  that the level fits the page outline; where it does not, leave `title` out
  and put your own heading of the right level above the fields (WCAG 1.3.1;
  KWCAG 5.2.4.2 제목 제공).
- On submit, move focus to the first field with an error, or summarise the
  errors at the top (WCAG 3.3.1).

## Tokens

Form parts are layout. `FormFooter` uses `bg.surface` with a `border.subtle`
top rule, `FormSection` `divider` uses `border.subtle`, and `FieldError` uses
`danger.fg`. Section descriptions and `FieldLabel` descriptions are
`fg.muted`.

## Related

- **FormControl** / **FormLabel**: the primitives under `FieldRow`.
- **FormIntegration**: wiring these to Formik or React Hook Form.
- **Modal**: `FormModalFooter` sits in `ModalFooter`.

## 문구

- 섹션 제목은 명사로 씁니다(기본 정보, 동작). 필드 문구 규칙은 Input과 Select 페이지에
  있습니다.
- 푸터 버튼에는 결과를 씁니다(저장, 만들기, 그룹 삭제). 디자인 시스템은 문구를 가지지
  않으므로 `cancelLabel`, `submitLabel`, `deleteLabel`은 앱의 번역에서 넘깁니다.
- `meta`에는 지시가 아니라 사실을 씁니다. 예: 오후 2:14에 저장됨, 10 크레딧.

## 접근성

이 부품들이 알아서 하는 일

- `FieldRow`는 라벨을 연결하고, `error`가 있으면 `aria-invalid`를 붙이며, 도움말과 오류
  문구를 `aria-describedby`로 가리킵니다. `required`를 주면 별표가 보이고 컨트롤도 필수로
  표시됩니다.
- `FormModalFooter`는 `<form>` 안에서 제출 버튼을 `type="submit"`으로 두어 Enter로
  제출되게 합니다. `onSubmit`은 포털로 그려지거나 `<form>`이 없는 모달에서만 넘깁니다.
  `isSubmitting`이면 모든 버튼이 비활성이 되어 요청 중에 모달이 닫히지 않습니다.
  `submitLoadingText`("저장 중")를 함께 넘기면 요청 중인 제출 버튼도 무엇을 하는지 말합니다.
- `hasError`인 `FormSection`이 접혀 있으면 펼침 화살표 대신 위험 표시가 보여 숨은
  오류를 놓치지 않습니다.

직접 챙겨야 하는 일

- **`FieldRow`가 닿지 않는 컨트롤에는 따로 이름을 줍니다.** `SelectField`,
  `ComboboxField`, `Slider`는 자기 라벨 부품에서 이름을 가져오므로 행의 라벨을
  `ariaLabel`로 넘깁니다(`ACCESSIBILITY.md` 1절).
- 펼친 `FormSection`과 `FormSectionHeader`는 제목을 `<h5>`로 그립니다. 그 수준이 화면 구조에
  맞는지 확인하고, 맞지 않으면 `title`을 비우고 필드 위에 알맞은 수준의 제목을 직접
  둡니다(WCAG 1.3.1, KWCAG 5.2.4.2 제목 제공).
- 제출할 때 오류가 있으면 첫 오류 필드로 초점을 옮기거나 위쪽에 오류를 모아 보여
  줍니다(WCAG 3.3.1).

## 토큰

Form 부품은 배치용입니다. `FormFooter`는 `bg.surface`에 `border.subtle` 윗선을,
`FormSection`의 `divider`는 `border.subtle`을, `FieldError`는 `danger.fg`를 씁니다.
섹션 설명과 `FieldLabel` 설명은 `fg.muted`입니다.

## 관련 컴포넌트

- **FormControl** / **FormLabel**: `FieldRow` 아래의 기본 부품.
- **FormIntegration**: Formik이나 React Hook Form과 연결하기.
- **Modal**: `FormModalFooter`는 `ModalFooter` 안에 들어갑니다.

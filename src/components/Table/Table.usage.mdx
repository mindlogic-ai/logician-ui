# Table

Rows of records that share the same columns, for reading and comparing
values: members, usage, invoices, API keys.

`TableContainer` › `Table` › `Thead` / `Tbody` › `Tr` › `Th` / `Td`. The
container draws the rounded border, scrolls horizontally, and tracks scroll
position for sticky columns.

## When to use

- A list where each item has the same attributes and the reader compares
  across rows: a member list, usage by model, call history.
- When the reader scans a column (a date, an amount, a status).

## When not to use

- Items that are read one at a time and have different shapes → `Card` in a
  list or grid.
- Two to five label–value pairs about one thing → a plain stack of `Text`.
- A hierarchy (groups inside groups) → `Tree`.
- Page layout. A table is for data only.

## 언제 쓰나요

- 항목마다 같은 속성이 있고 행끼리 비교해 읽는 목록: 멤버 목록, 모델별 사용량, 호출

- 하나씩 읽는 항목이고 모양이 서로 다르다면 목록이나 격자 안의 `Card`를 씁니다.
- 한 대상의 라벨과 값 두세 쌍이라면 `Text`를 쌓아서 보여 줍니다.
- 그룹 안의 그룹 같은 계층은 `Tree`를 씁니다.
- 페이지 레이아웃에는 쓰지 않습니다. 표는 데이터에만 씁니다.

## Content

- Column headers are short nouns: 이름, 그룹, 사용 크레딧. Put the unit in
  the header, not in every cell.
- Numbers and amounts align to the end (`textAlign="end"`); text aligns to the
  start.
- An empty value is "—", not a blank cell, so the reader knows nothing is
  missing from the page.
- Keep a status in its own column with a `Badge`, rather than colouring a
  whole row.

## Accessibility

What Table does for you:

- It renders native table elements (`<table>`, `<th>`, `<td>`), so screen
  readers announce row and column positions.
- A clickable `Tr` gets a pointer, a hover tint and a 2px inset focus
  outline when focused from the keyboard. Static rows never highlight.
- Sticky header and sticky columns get an opaque background, so text never
  shows through.

What you still have to do:

- **A clickable row is not a button by itself.** `Tr` only styles it. Give
  it `tabIndex={0}` and handle Enter in `onKeyDown` (WCAG 2.1.1), or better,
  put a real link or button in the row and let that be the target (WCAG
  4.1.2). Never put a button inside a row that is also `role="button"`
  (nested interactive controls, see `ACCESSIBILITY.md` §3).
- **Row states need words** (WCAG 1.4.1). `state` only tints the row.
- **Name icon-only buttons in cells**: `aria-label` on the `IconButton`
  (WCAG 4.1.2). For an `ExpandingTr` toggle, also pass `aria-expanded`.
- Give the table a caption or a heading next to it so it has a name
  (WCAG 1.3.1).
- A cell cut off with an ellipsis hides content. Use `wrap`, or make the full
  value available another way (WCAG 1.4.10).

## 문구

- 열 머리글은 짧은 명사로 씁니다: 이름, 그룹, 사용 크레딧. 단위는 칸마다 쓰지 않고
  머리글에 씁니다.
- 숫자와 금액은 끝에 맞추고(`textAlign="end"`), 글은 앞에 맞춥니다.
- 값이 없으면 빈칸 대신 "—"를 써서, 화면에서 빠진 것이 없다는 것을 알립니다.
- 상태는 행 전체에 색을 칠하지 않고 `Badge`로 따로 열을 둡니다.

## 접근성

Table이 알아서 하는 일

- 기본 표 요소(`<table>`, `<th>`, `<td>`)로 그리므로 화면 낭독기가 행과 열의 위치를
  읽어 줍니다.
- 누를 수 있는 `Tr`에는 포인터, 호버 배경, 키보드 초점 시 안쪽 2px 테두리가 생깁니다.
  누를 수 없는 행은 강조되지 않습니다.
- 고정 머리글과 고정 열은 불투명한 배경을 가지므로 뒤의 글자가 비치지 않습니다.

직접 챙겨야 하는 일

- **누를 수 있는 행이 저절로 버튼이 되지는 않습니다.** `Tr`은 모양만 바꿉니다.
  `tabIndex={0}`를 주고 `onKeyDown`에서 Enter를 처리하거나(WCAG 2.1.1), 행 안에 실제
  링크나 버튼을 두고 그것을 누르게 하는 편이 낫습니다(WCAG 4.1.2). `role="button"`인
  행 안에 다시 버튼을 넣지 않습니다(상호작용 요소 중첩, `ACCESSIBILITY.md` 3절).
- **행 상태는 문구로도 알립니다**(WCAG 1.4.1). `state`는 배경색만 바꿉니다.
- **칸 안의 아이콘 버튼에는 이름을 붙입니다.** `IconButton`에 `aria-label`을 줍니다
  (WCAG 4.1.2). `ExpandingTr`을 여닫는 버튼에는 `aria-expanded`도 줍니다.
- 표에 캡션을 달거나 옆에 제목을 두어 이름을 붙입니다(WCAG 1.3.1).
- 말줄임표로 잘린 칸은 내용을 숨깁니다. `wrap`을 쓰거나 전체 값을 다른 방법으로
  볼 수 있게 합니다(WCAG 1.4.10).

## Related

- **Badge**: a status in its own column.
- **Pagination**: long lists split into pages.
- **Checkbox**: row selection for bulk actions, with `state="selected"`.
- **Tree**: hierarchical data.
- **Card**: items with different shapes.

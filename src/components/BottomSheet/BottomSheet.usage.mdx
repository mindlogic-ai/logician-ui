# BottomSheet

A panel that rises from the bottom edge of a phone screen. The user can drag it
between snap points or swipe it away.

## When to use

- On a phone, to pick one item from a list: a node palette in the workflow
  editor, an answer to a question the assistant asks.
- On a phone, for a few related choices the user applies together, such as
  filters.
- Next to a canvas the user keeps working on: a non-modal sheet
  (`modal={false}`) resting on a snap point leaves the page usable.

## When not to use

- On a desktop layout → `Modal` for a task, `Menu` or `Popover` for options
  next to their trigger.
- To confirm something that cannot be undone → `Modal`. A swipe should never
  be the only thing between the user and a deletion.
- For a result or status → `Toast` or `Banner`.
- For a long form → a page. The sheet is capped at 85% of the screen height.

# BottomSheet

휴대폰 화면 아래 가장자리에서 올라오는 패널입니다. 사용자가 끌어서 멈춤 지점 사이를

## 언제 쓰나요

- 휴대폰에서 목록 중 하나를 고르게 할 때: 워크플로 편집기의 노드 팔레트, 어시스턴트가
  묻는 질문의 답.
- 휴대폰에서 함께 적용하는 몇 가지 선택지를 보일 때: 필터.
- 사용자가 계속 작업하는 캔버스 옆에 둘 때: 멈춤 지점에 걸쳐 둔 비모달 시트
  (`modal={false}`)는 뒤의 페이지를 그대로 쓸 수 있게 둡니다.

## 언제 쓰지 않나요

- 데스크톱 화면에서는 작업에 `Modal`을, 버튼 옆 선택지에 `Menu`나 `Popover`를 씁니다.

  일어나서는 안 됩니다.
- 결과나 상태는 `Toast`나 `Banner`로 알립니다.
- 긴 양식은 페이지에 둡니다. 시트 높이는 화면의 85%까지만 늘어납니다.

## Content

- **Header:** a noun or a short task name, no full stop: "노드 추가", "필터".
- **Rows:** a label and, if needed, one line of hint in `fg.muted`.
- **Footer buttons:** verbs ("적용", "초기화"), at most two.

## Accessibility

What BottomSheet does for you:

- `BottomSheetHeader` becomes the sheet's title, which the content's
  `aria-labelledby` points at (WCAG 4.1.2).
- When modal, it traps focus in the sheet and locks the page's scroll.
  `Escape` closes it (WCAG 2.1.1).
- `BottomSheetCloseButton` carries a translated `aria-label` (닫기 / Close).
- The grabber is `aria-hidden`: it is a pointer affordance, and dragging is
  never the only way to close the sheet (WCAG 2.5.1).
- `BottomSheetBody` scrolls inside the sheet; a drag starts from the body only
  when the list is scrolled to the top, so scrolling never drags the sheet.

What you still have to do:

- **Always render `BottomSheetHeader`.** Without it the sheet has no name.
- **Keep a close button or a footer action.** A swipe or an outside tap is not
  available to keyboard and switch users.
- Put `BottomSheetCloseButton` directly inside `BottomSheetContent`, next to
  the header, not inside it.
- A non-modal sheet does not trap focus: `Tab` can leave it for the page
  behind. Check that the tab order between the two still makes sense.

The scrim is `blackAlpha.500`, a fixed value rather than a semantic token.

## 문구

- **헤더:** 명사나 짧은 작업 이름을 쓰고 마침표를 찍지 않습니다. "노드 추가", "필터".
- **목록 한 줄:** 라벨 하나와, 필요하면 `fg.muted`로 쓴 도움말 한 줄.
- **푸터 버튼:** 동사("적용", "초기화")로 두 개까지 씁니다.

## 접근성

BottomSheet가 알아서 하는 일

- `BottomSheetHeader`가 시트의 제목이 되고, 콘텐츠의 `aria-labelledby`가 이 제목을
  가리킵니다(WCAG 4.1.2).
- 모달일 때는 초점을 시트 안에 가두고 페이지 스크롤을 막습니다. `Escape`로 닫힙니다
  (WCAG 2.1.1).
- `BottomSheetCloseButton`에는 번역된 `aria-label`(닫기 / Close)이 붙어 있습니다.
- 손잡이는 `aria-hidden`입니다. 포인터용 표시일 뿐이고, 끌기만이 시트를 닫는 유일한
  방법이 되지 않습니다(WCAG 2.5.1).
- `BottomSheetBody`는 시트 안에서 스크롤됩니다. 목록이 맨 위에 있을 때만 본문에서 끌기가
  시작되므로, 목록을 스크롤하다가 시트가 끌려 내려가지 않습니다.

직접 챙겨야 하는 일

- **`BottomSheetHeader`를 언제나 둡니다.** 헤더가 없으면 시트에 이름이 없습니다.
- **닫기 버튼이나 푸터 동작을 남깁니다.** 쓸어내리기나 바깥 누르기는 키보드나 스위치
  사용자가 쓸 수 없습니다.
- `BottomSheetCloseButton`은 헤더 안이 아니라 헤더 옆, `BottomSheetContent`의 바로
  아래에 둡니다.
- 비모달 시트는 초점을 가두지 않으므로 `Tab`으로 뒤의 페이지로 나갈 수 있습니다. 시트와
  페이지 사이의 탭 순서가 자연스러운지 확인합니다.

# Modal

A dialog that stops the page until the user finishes or dismisses one short
task: a confirmation, a small form, a decision.

## When to use

- To confirm an action that cannot be undone: deleting a member, revoking a key.
- For a short form that belongs to the current page: adding a domain, renaming
  a group, setting a credit limit.
- For a one-time message the user must read before going on, such as an
  announcement or the first step of onboarding.

## When not to use

- To say that something worked → `Toast`. A modal that only says "저장되었습니다"
  costs a click and teaches users to dismiss modals without reading.
- For a status that should stay on the page → `Banner`.
- For a few options next to the thing they act on → `Menu`, or `Popover` if the
  panel holds controls.
- On a phone, for a list the user picks from → `BottomSheet`.
- For long or multi-step work, or anything the user needs to compare with the
  page behind it → a page or a side panel, not a modal.

## Pick the kind first

Most modals are one of four kinds. Use the preset for it instead of assembling
`Modal` parts; the title, buttons, width and backdrop behaviour come with it.

| Kind | Component | Backdrop click | Buttons |
| --- | --- | --- | --- |
| Confirm | `ConfirmModal` | Closes | Cancel, then the action |
| Destructive confirm | `ConfirmModal tone="danger"` | Closes | Cancel, then a red action; name the target in the title |
| Input form | `FormModal` | Closes while untouched; once something is typed it stays and shakes | `FormModalFooter`: Cancel, then Save |
| View or result | `ViewModal` | Closes | One Close |

All four require a title, which goes in the header and names the dialog. Edit
modals carry no delete: delete from the list, in a row or card menu that opens a
`ConfirmModal tone="danger"`. Assemble `Modal` yourself only when none of these
fit.

## 언제 쓰지 않나요

- 작업이 잘 끝났다는 소식만 전한다면 `Toast`를 씁니다. "저장되었습니다"만 담긴 모달은

- 대상 옆에 선택지 몇 개를 보이려면 `Menu`를, 그 안에 입력 컨트롤이 있다면
  `Popover`를 씁니다.
- 휴대폰에서 목록 중 하나를 고르게 할 때는 `BottomSheet`를 씁니다.
- 길거나 여러 단계로 된 작업, 뒤의 페이지와 비교해야 하는 작업은 모달이 아니라 페이지나
  사이드 패널에 둡니다.

## 먼저 종류를 고르세요

모달은 대부분 네 종류 중 하나입니다. `Modal` 부품을 조립하지 말고 종류에 맞는 컴포넌트를

| 종류 | 컴포넌트 | 배경 클릭 | 버튼 |
| --- | --- | --- | --- |
| 확인 | `ConfirmModal` | 닫힘 | 취소, 동작 |
| 위험 확인 | `ConfirmModal tone="danger"` | 닫힘 | 취소, 빨간 동작. 제목에 대상 이름 |
| 입력 폼 | `FormModal` | 입력 전이면 닫힘, 입력 후에는 닫히지 않고 흔들림 | `FormModalFooter`: 취소, 저장 |

## Content

- **Title:** a question or the name of the task, in sentence case, with no full
  stop. "멤버를 삭제할까요?", "도메인 추가". Not "알림" or "확인".
- **Body:** what will happen and what cannot be undone, in one or two
  sentences. Name the object ("김민지 님").
- **Buttons:** verbs that repeat the title's action ("삭제", "추가"). The
  dismiss button is "취소". Destructive actions use `variant="danger"`.
- **Subtitle** (`ModalHeader subtitle`): one line of context under the title,
  not a second paragraph of body text.
- Footer buttons share the row equally; keep them to two.

## Accessibility

What Modal does for you:

- Renders `role="dialog"` with `aria-modal`. `ModalHeader`'s children become
  the dialog's accessible name and `subtitle` its description (WCAG 4.1.2).
  Plain text is rendered as an `<h2>`; your own element is wrapped in a
  `<div>`, so it is never nested inside a heading.
- Moves focus into the dialog when it opens, keeps it there, and returns it to
  the trigger when it closes (WCAG 2.4.3). `Escape` closes it (WCAG 2.1.1);
  so does a click on the backdrop unless you pass
  `closeOnInteractOutside={false}`.
- Locks the page's scroll while open.

What you still have to do:

- **Give every modal a `ModalHeader`.** Without one the dialog has no name and a
  screen reader announces only "dialog". If the design has no visible title,
  pass `aria-label` to `ModalContent`.
- **Name the close button in the user's language.** `ModalCloseButton` uses
  Chakra's `CloseButton`, whose default `aria-label` is the English "Close".
  Pass `aria-label="닫기"` (or your translation) on Korean screens (WCAG
  3.1.2).
- Keep a way out from the keyboard: if you remove `ModalCloseButton`, the
  footer needs a "취소" button.
- For a destructive confirmation, Chakra's `role="alertdialog"` is available
  on the root.

## Tokens

The panel colour comes from Chakra's Dialog recipe; the rest is set in
`ModalHeader` and `ModalFooter`.

## 문구

- **제목:** 질문이나 작업 이름을 쓰고 마침표를 찍지 않습니다. "멤버를 삭제할까요?",
  "도메인 추가"처럼 씁니다. "알림", "확인"은 쓰지 않습니다.
- **본문:** 무슨 일이 일어나는지, 무엇을 되돌릴 수 없는지를 한두 문장으로 씁니다. 대상의
  이름("김민지 님")을 밝힙니다.
- **버튼:** 제목의 동작을 되풀이하는 동사("삭제", "추가")를 씁니다. 닫는 버튼은
  "취소"입니다. 되돌릴 수 없는 동작에는 `variant="danger"`를 씁니다.
- **부제목**(`ModalHeader`의 `subtitle`): 제목 아래 맥락 한 줄입니다. 본문을 한 문단 더
  쓰는 자리가 아닙니다.
- 푸터의 버튼은 같은 너비로 나뉩니다. 두 개까지만 둡니다.

## 접근성

Modal이 알아서 하는 일

- `role="dialog"`와 `aria-modal`을 붙입니다. `ModalHeader`의 내용이 대화상자의 접근
  가능한 이름이 되고, `subtitle`은 설명이 됩니다(WCAG 4.1.2). 글자만 넣으면 `<h2>`로,
  직접 만든 요소를 넣으면 `<div>`로 감싸므로 제목 안에 제목이 들어가지 않습니다.
- 열리면 초점을 대화상자 안으로 옮기고 그 안에 가두며, 닫히면 연 버튼으로 돌려놓습니다
  (WCAG 2.4.3). `Escape`로 닫히고(WCAG 2.1.1), `closeOnInteractOutside={false}`를
  넘기지 않으면 배경을 눌러도 닫힙니다.
- 열려 있는 동안 페이지 스크롤을 막습니다.

직접 챙겨야 하는 일

- **모든 모달에 `ModalHeader`를 둡니다.** 헤더가 없으면 대화상자에 이름이 없어 화면
  낭독기는 "대화상자"라고만 읽습니다. 보이는 제목이 없는 디자인이라면 `ModalContent`에
  `aria-label`을 넘깁니다.
- **닫기 버튼 이름을 사용자의 언어로 붙입니다.** `ModalCloseButton`은 Chakra의
  `CloseButton`을 쓰는데, 기본 `aria-label`이 영어 "Close"입니다. 한국어 화면에서는
  `aria-label="닫기"`(또는 번역 문자열)를 넘깁니다(WCAG 3.1.2).
- 키보드로 빠져나갈 길을 남깁니다. `ModalCloseButton`을 빼면 푸터에 "취소" 버튼이
  있어야 합니다.
- 되돌릴 수 없는 동작의 확인 창에는 Chakra가 제공하는 `role="alertdialog"`를 루트에
  줄 수 있습니다.

- **Popover**: a small panel of controls that leaves the page usable.

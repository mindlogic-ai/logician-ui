# Masonry

Equal-width columns that pack items of different heights without gaps,
re-measuring as items resize. FactChat uses it for the model and voice menus.

## When to use

- Unordered groups or cards whose heights differ a lot, where a grid would
  leave holes.

## When not to use

- Items with similar heights → `SimpleGrid` / `Grid`, which keeps row order.
- Anything with an order (steps, a ranking, a timeline, search results) →
  a list or a grid. Masonry's reading order is column by column.
- A data list → `Table`.

# Masonry

너비가 같은 열에 높이가 다른 항목을 빈틈없이 채우고, 항목 크기가 바뀌면 다시 재는

  Masonry의 읽기 순서는 열 단위입니다.
- 데이터 목록은 `Table`을 씁니다.

## Accessibility

What Masonry does for you:

- Nothing beyond layout. It renders plain boxes, one column after another.

What you still have to do:

- **Keep the content order-free** (WCAG 1.3.2, 2.4.3). The DOM order is
  column 1 top to bottom, then column 2, so Tab and a screen reader follow
  columns, not the rows a sighted reader sees.
- **Set `numCols` for the viewport** with `useBreakpointValue`; at 320px wide
  one column avoids sideways scrolling (WCAG 1.4.10).

## Tokens

Masonry sets no colour tokens.

</En>

## 접근성

Masonry가 알아서 하는 일

- 레이아웃 말고는 없습니다. 열을 하나씩 차례로 그리는 일반 상자입니다.

직접 챙겨야 하는 일

- **순서가 없는 내용에만 씁니다**(WCAG 1.3.2, 2.4.3). DOM 순서가 1열 위에서 아래, 그다음
  2열이라, Tab과 화면 낭독기는 눈에 보이는 행이 아니라 열을 따라갑니다.
- **화면 너비에 맞게 `numCols`를 정합니다.** `useBreakpointValue`를 쓰고, 폭 320px에서는
  한 열로 두어 가로 스크롤을 막습니다(WCAG 1.4.10).

## 토큰

Masonry는 색 토큰을 쓰지 않습니다.

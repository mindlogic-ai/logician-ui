# Form integration

How the form controls connect to a form library. There is no
`FormIntegration` component: this page and the stories under
**Examples/Form Integration** show the wiring.

## The rule

Put field state on the field, not on the control:

1. One `FieldRow` (or `FormControl`) per field. Set `error` on it from the
   library's error for that field; `invalid` follows, and `aria-invalid` and
   `aria-describedby` reach the control.
2. Pass the library's `value`, `onChange`, `onBlur` and `name` to the control.
   `Input` re-emits change and blur events with `name` and the processed value
   (trimmed, or digits only with `maskNumber`), so Formik's `handleChange` and
   React Hook Form's `field.onChange` both work.
3. Controls with their own value API take it directly: `SelectField` /
   `ComboboxField` `onChange(value)`, `RadioGroup` `onValueChange`, `Checkbox`
   / `Switch` `onCheckedChange`, `Slider` `onValueChange` (an array),
   `FileInput` `onChange(files)`. With React Hook Form, wrap them in a
   `Controller`.

## When to use which library

- **React Hook Form** with a `Controller` per non-text control: what FactChat
  uses for admin and studio forms.
- **Formik + Yup**: the first example below.
- **Plain state**: small forms, the second example.

# 폼 연동

폼 컨트롤을 폼 라이브러리에 연결하는 방법입니다. `FormIntegration`이라는 컴포넌트는
없습니다. 이 페이지와 **Examples/Form Integration** 아래 스토리가 연결 방법을 보여
줍니다.

## 원칙

필드 상태는 컨트롤이 아니라 필드에 둡니다.

1. 필드마다 `FieldRow`(또는 `FormControl`)를 하나씩 둡니다. 라이브러리가 그 필드에
   대해 준 오류를 `error`에 넣으면 `invalid`도 따라 바뀌고, `aria-invalid`와
   `aria-describedby`가 컨트롤까지 전달됩니다.
2. 라이브러리의 `value`, `onChange`, `onBlur`, `name`을 컨트롤에 넘깁니다. `Input`은
   변경·이탈 이벤트를 `name`과 가공한 값(공백을 정리한 값, `maskNumber`면 숫자만)으로
   다시 만들어 보내므로 Formik의 `handleChange`와 React Hook Form의 `field.onChange`가
   모두 동작합니다.
3. 값을 다루는 방식이 따로 있는 컨트롤은 그 방식을 그대로 씁니다. `SelectField`·
   `ComboboxField`는 `onChange(value)`, `RadioGroup`은 `onValueChange`, `Checkbox`·
   `Switch`는 `onCheckedChange`, `Slider`는 `onValueChange`(배열), `FileInput`은
   `onChange(files)`입니다. React Hook Form에서는 `Controller`로 감쌉니다.

## Pitfalls

- **`trimWhiteSpace` trims on every keystroke**, so a name with a space can
  only be pasted. Trim at submit instead.
- **`maskNumber` needs `type="number"`** and then renders a text input; `min`
  and `max` do nothing there. Validate the range in the schema.
- **`SelectField` inside `FieldRow` needs `ariaLabel`** with the row's label;
  the row's label does not name it.
- **Don't set `invalid` on the control alone.** It paints the border without
  telling assistive technology (WCAG 3.3.1).

## Accessibility

- Every field has a visible label (WCAG 3.3.2; KWCAG 5.3.4.1 레이블 제공), and
  every error is text under its field (WCAG 3.3.1).
- After a failed submit, move focus to the first invalid field or to an error
  summary at the top.
- Do not disable the submit button until the form is valid without saying
  why; the user cannot find out what is missing. Validate on submit and show
  the errors.

## Tokens

None of its own; see Input, Select and Form.

## 자주 하는 실수

- **`trimWhiteSpace`는 입력할 때마다 공백을 지웁니다.** 그래서 공백이 든 이름은 붙여
  넣기로만 넣을 수 있습니다. 공백 정리는 제출할 때 합니다.
- **`maskNumber`는 `type="number"`가 있어야 동작하고**, 그때는 텍스트 입력란을 그립니다.
  `min`과 `max`는 효과가 없으므로 범위는 스키마에서 검사합니다.
- **`FieldRow` 안의 `SelectField`에는 행의 라벨을 `ariaLabel`로 넘깁니다.** 행의 라벨은
  셀렉트의 이름이 되지 않습니다.
- **컨트롤에만 `invalid`를 주지 않습니다.** 테두리만 칠하고 보조기술에는 알리지
  않습니다(WCAG 3.3.1).

## 접근성

- 모든 필드에 보이는 라벨을 두고(WCAG 3.3.2, KWCAG 5.3.4.1 레이블 제공), 모든 오류는 해당
  필드 아래에 문구로 보여 줍니다(WCAG 3.3.1).
- 제출에 실패하면 첫 오류 필드나 위쪽의 오류 요약으로 초점을 옮깁니다.
- 이유를 알리지 않은 채 폼이 유효해질 때까지 제출 버튼을 비활성으로 두지 않습니다.
  무엇이 빠졌는지 알 수 없습니다. 제출할 때 검사하고 오류를 보여 줍니다.

## 토큰

따로 정한 토큰이 없습니다. Input, Select, Form 페이지를 보세요.

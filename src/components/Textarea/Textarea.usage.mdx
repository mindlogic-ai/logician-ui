# Textarea

A multi-line text field for prose the user writes: instructions, descriptions,
messages.

## When to use

- Text that can run to several sentences or lines: a chatbot's system
  instructions, a description, a reason for a request.

## When not to use

- A one-line value such as a name or a title → `Input`.
- The chat composer, which grows with the message and sends on Enter → the
  chat input in your app, not this field.
- Formatted text (headings, lists, links) → a rich-text editor.

# Textarea

사용자가 직접 쓰는 여러 줄짜리 글(지시문, 설명, 메시지)을 받는 입력란입니다.

## 언제 쓰나요

- 몇 문장이나 몇 줄로 길어질 수 있는 글: 챗봇의 시스템 지시문, 설명, 요청 사유.

## 언제 쓰지 않나요

- 이름이나 제목처럼 한 줄이면 되는 값은 `Input`을 씁니다.
- 내용에 따라 높이가 늘고 Enter로 보내는 채팅 입력창은 이 컴포넌트가 아니라 앱의 채팅
  입력 컴포넌트를 씁니다.
- 제목, 목록, 링크 같은 서식이 필요한 글은 리치 텍스트 편집기를 씁니다.

<En>

- `rows` sets the height. Textarea is fixed at `resize="none"` and does not
  grow with its content; pass `resize="vertical"` if the user should be able to
  drag it taller.
- `invalid` changes the border only. Put the field in `FieldRow` with `error`
  so assistive technology hears it too.
- `readOnly` and `disabled` look the same as on `Input`.

## Content

- Label and error rules are the same as `Input`.
- Size the field to the expected answer: `rows={3}` for a short reason, more
  for instructions. Height is a hint about how much to write.
- Put examples in helper text, not in a long placeholder that vanishes on the
  first keystroke.

## Accessibility

What Textarea does for you:

- Renders a native `<textarea>`. Enter inserts a new line; Tab moves focus out.
- Shows a `primary.main` focus border and ring (WCAG 2.4.7), and inside
  `FormControl` / `FieldRow` it is labelled and gets `aria-invalid` and
  `aria-describedby` from the field.

What you still have to do:

- Give it a visible label with `FieldRow` or `FormControl` + `FormLabel`
  (WCAG 4.1.2; KWCAG 5.3.4.1 레이블 제공).
- Put errors in words with `FieldRow` `error`, not as a red border alone
  (WCAG 1.4.1, 3.3.1).
- If you set `maxLength`, show the count; the browser stops input silently at
  the limit.

## 문구

- 라벨과 오류 문구 규칙은 `Input`과 같습니다.
- 예상되는 답의 길이에 맞춰 높이를 정합니다. 짧은 사유는 `rows={3}`, 지시문은 그보다
  길게 잡습니다. 높이는 얼마나 써야 하는지 알려 주는 단서입니다.
- 예시는 첫 글자를 입력하면 사라지는 긴 플레이스홀더가 아니라 도움말에 씁니다.

## 접근성

Textarea가 알아서 하는 일

- 네이티브 `<textarea>`를 그립니다. Enter는 줄을 바꾸고, Tab은 초점을 다음 요소로
  옮깁니다.
- 초점을 받으면 `primary.main` 테두리와 링을 보여 주고(WCAG 2.4.7), `FormControl`이나
  `FieldRow` 안에서는 라벨과 연결되며 `aria-invalid`와 `aria-describedby`를 받습니다.

직접 챙겨야 하는 일

- `FieldRow`나 `FormControl`과 `FormLabel`로 보이는 라벨을 붙입니다(WCAG 4.1.2, KWCAG
  5.3.4.1 레이블 제공).
- 오류는 빨간 테두리만이 아니라 `FieldRow`의 `error`로 문구를 함께 보여 줍니다(WCAG
  1.4.1, 3.3.1).
- `maxLength`를 정했다면 글자 수를 보여 줍니다. 브라우저는 제한에 닿으면 아무 안내 없이
  입력을 막습니다.

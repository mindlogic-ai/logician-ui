# Input

A single-line text field: names, email addresses, amounts, search terms.

## When to use

- One line of free text the user types: a name, an email address, a URL.
- A number the user types exactly, such as a credit limit. Use
  `type="number"` with `maskNumber` to show thousands separators.
- A search or filter box, with a `leftIcon`.

## When not to use

- More than one line, or text that wraps → `Textarea`.
- A password or secret → `PasswordInput`.
- A short one-time code typed box by box → `PinInput`.
- A choice from a known list → `SelectField`, `ComboboxField`, `Radio`.
- A date or month → `SingleDatePicker`, `RangeDatePicker`, `MonthPicker`.
- A rough value on a scale, where the exact number does not matter → `Slider`.

# Input

한 줄짜리 텍스트 입력란입니다. 이름, 이메일 주소, 금액, 검색어에 씁니다.

## 언제 쓰나요

- 사용자가 직접 입력하는 한 줄짜리 텍스트: 이름, 이메일 주소, URL.
- 정확하게 입력해야 하는 숫자(예: 크레딧 한도). 천 단위 쉼표가 필요하면
  `type="number"`와 `maskNumber`를 함께 씁니다.
- 검색창이나 필터 입력란. 이때는 `leftIcon`에 아이콘을 넣습니다.

## 언제 쓰지 않나요

- 두 줄 이상이거나 줄바꿈이 필요한 글은 `Textarea`를 씁니다.
- 비밀번호나 비밀 값은 `PasswordInput`을 씁니다.
- 한 칸에 한 글자씩 넣는 짧은 인증 코드는 `PinInput`을 씁니다.
- 정해진 목록에서 고르는 값은 `SelectField`, `ComboboxField`, `Radio`를 씁니다.
- 날짜나 월은 `SingleDatePicker`, `RangeDatePicker`, `MonthPicker`를 씁니다.
- 정확한 숫자보다 대략적인 위치가 중요한 값은 `Slider`를 씁니다.

<En>

| Prop             | What it does                                                                                                                  | Use for                                                                |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `maskNumber`     | Only with `type="number"`. Renders a text input that shows `2,000,000` while `onChange` receives the digits (`2000000`).      | Amounts, limits, counts                                                |
| `noSpaces`       | Blocks the space key and strips every space, including pasted ones.                                                           | Email addresses, IDs, codes                                            |
| `trimWhiteSpace` | Blocks a leading space and trims **both ends on every keystroke**, so a space between two words cannot be typed, only pasted. | Single-word values only. Never names or titles; trim at submit instead |
| `invalid`        | Red border only. It does not tell assistive technology anything; see Accessibility.                                           | With `FieldRow` `error`                                                |
| `readOnly`       | `bg.subtle` fill and muted text. The value can still be selected and copied.                                                  | Values the user may see but not change                                 |
| `disabled`       | The fixed `disabled.*` pair, not reduced opacity.                                                                             | A field that does not apply right now                                  |

Good to know:

- While a Korean IME is composing, Enter is swallowed, so a half-typed syllable
  never submits the form.
- `onKeyDown` is only called for Enter. Listen on a wrapper if you need other
  keys.
- On touch devices the text is raised to 16px so iOS Safari does not zoom the
  page on focus.

## Content

- Label: a noun phrase in sentence case, no colon ("Work email", not
  "Work Email:"). Korean labels are nouns too: 업무용 이메일, not 이메일을
  입력하세요.
- Placeholder: an example of the format (`name@company.com`), never the label
  and never an instruction the user needs after they start typing.
- Helper text: one sentence on what happens with the value or which format is
  accepted. Put it in `FieldRow` `helperText`, not in the placeholder.
- Error text: say what is wrong and how to fix it, in one sentence: 이메일 주소
  형식이 아닙니다.

## Accessibility

What Input does for you:

- Renders a native `<input>`, so Tab, typing, selection and copy and paste
  work as the browser provides.
- Shows a visible focus state: a `primary.main` border and 1px ring (WCAG
  2.4.7).
- Inside `FormControl` or `FieldRow` it takes the field's id, so the label is
  associated, and it picks up `aria-invalid`, `required` and the
  `aria-describedby` that points at helper and error text.

What you still have to do:

- **Name every field.** Use `FieldRow` `label` or `FormControl` + `FormLabel`.
  A placeholder is not a name, and an icon is not either (WCAG 4.1.2; KWCAG
  5.3.4.1 레이블 제공).
- **Mark errors on the field, not on the input.** The `invalid` prop changes
  the border only. Set `error` on `FieldRow` (or `invalid` on `FormControl`)
  so the state and the message reach assistive technology (WCAG 3.3.1).
- **Say what the field is for** with `type` and `autoComplete` (`email`,
  `name`, `tel`), so browsers and assistive tools can fill it (WCAG 1.3.5).
- An icon-only `rightIcon` that does something (clear, search) has to be a
  button with an `aria-label`. A decorative `leftIcon` gets `aria-hidden`.

## 문구

- 라벨: 문장형 대소문자의 명사구로 쓰고 쌍점을 붙이지 않습니다("Work email",
  "Work Email:"이 아님). 한국어 라벨도 명사로 씁니다. "이메일을 입력하세요"가 아니라
  "업무용 이메일"입니다.
- 플레이스홀더: 형식의 예(`name@company.com`)만 씁니다. 라벨을 대신하지 않고, 입력을
  시작한 뒤에도 필요한 안내를 넣지 않습니다.
- 도움말: 값이 어디에 쓰이는지나 받는 형식을 한 문장으로 씁니다. 플레이스홀더가 아니라
  `FieldRow`의 `helperText`에 넣습니다.
- 오류 문구: 무엇이 잘못됐고 어떻게 고치는지 한 문장으로 씁니다. 예: 이메일 주소
  형식이 아닙니다.

## 접근성

Input이 알아서 하는 일

- 네이티브 `<input>`을 그리므로 Tab 이동, 입력, 선택, 복사와 붙여 넣기가 브라우저
  기본대로 동작합니다.
- 초점을 받으면 `primary.main` 테두리와 1px 링으로 눈에 띄게 표시합니다(WCAG 2.4.7).
- `FormControl`이나 `FieldRow` 안에 두면 필드의 id를 받아 라벨과 연결되고,
  `aria-invalid`, `required`, 도움말과 오류 문구를 가리키는 `aria-describedby`도
  함께 받습니다.

직접 챙겨야 하는 일

- **모든 입력란에 이름을 붙입니다.** `FieldRow`의 `label`이나 `FormControl`과
  `FormLabel`을 씁니다. 플레이스홀더나 아이콘은 이름이 아닙니다(WCAG 4.1.2, KWCAG
  5.3.4.1 레이블 제공).
- **오류는 입력란이 아니라 필드에 표시합니다.** `invalid` 속성은 테두리만 바꿉니다.
  `FieldRow`에 `error`를 넘기거나 `FormControl`에 `invalid`를 주어야 오류 상태와 문구가
  보조기술에 전달됩니다(WCAG 3.3.1).
- **입력란의 용도를 밝힙니다.** `type`과 `autoComplete`(`email`, `name`, `tel`)를
  지정하면 브라우저와 보조 도구가 값을 채워 줄 수 있습니다(WCAG 1.3.5).
- 지우기나 검색처럼 동작하는 `rightIcon`은 `aria-label`이 있는 버튼이어야 합니다.
  꾸밈용 `leftIcon`에는 `aria-hidden`을 붙입니다.

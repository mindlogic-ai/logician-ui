# IconButton

A round button with an icon and no visible label, for actions so common that
the icon alone is enough: close, copy, edit, delete, send.

## When to use

- Toolbars and per-item actions where a row of labels would crowd the
  content: the copy, edit and share actions under a chat message, the delete
  icon on a list row.
- Close and back in dialogs, drawers and panels.
- The send button of a chat composer (`variant="action"`).

## When not to use

- The icon is not universally understood, or the action is rare or
  destructive enough that the user should read it → `Button` with an icon and
  a label.
- Opening a menu of more actions on its own → wrap the IconButton in
  `Menu.Trigger asChild`, so the menu supplies the popup ARIA.
- A setting that stays on or off → `Switch`.
- "Load more" at the end of a list → `SeeMoreButton`.

# IconButton

글자 없이 아이콘만 있는 둥근 버튼입니다. 닫기, 복사, 수정, 삭제, 보내기처럼 아이콘만
봐도 알 만큼 흔한 동작에 씁니다.

## 언제 쓰나요

- 라벨을 늘어놓으면 내용이 답답해지는 툴바와 항목별 동작: 채팅 메시지 아래의 복사,
  수정, 공유, 목록 행의 삭제 아이콘.
- 대화상자, 서랍, 패널의 닫기와 뒤로 가기.
- 채팅 입력창의 보내기 버튼(`variant="action"`).

## 언제 쓰지 않나요

- 누구나 아는 아이콘이 아니거나, 드물게 쓰거나, 사용자가 글로 읽어야 할 만큼 위험한
  동작이라면 아이콘과 라벨을 함께 넣은 `Button`을 씁니다.
- 더 많은 동작을 담은 메뉴를 IconButton 혼자 열게 하지 않습니다. `Menu.Trigger asChild`로
  감싸 메뉴가 팝업 ARIA를 붙이게 합니다.
- 켜짐과 꺼짐이 유지되는 설정이라면 `Switch`를 씁니다.
- 목록 끝의 "더보기"라면 `SeeMoreButton`을 씁니다.

<En>

| Variant | Means | Use for |
| --- | --- | --- |
| `ghost` (default) | A routine action next to content. Glyph `fg.icon`, darkens on hover | 닫기, 복사, 수정, 뒤로 가기 |
| `secondary` | Ghost with an outline, so it reads as a button on its own | 이전 / 다음, 일시정지, 수정 취소 |
| `primary` | The one main icon action of its area. Black fill | 재생, 수정 저장 (check icon) |
| `danger` | Confirms a destructive step. Red fill | Rare; prefer `ghost` + `isDestructive` |
| `action` | Send. Coral fill, dark arrow | The chat composer's 보내기, nothing else |

`isDestructive` turns the glyph `danger.fg` on `ghost` and `secondary`; it is
ignored on the filled roles.

In FactChat, `ghost` makes up most IconButtons; `secondary` is used about a
fifth as often, and the filled roles are rare. Start from `ghost`.

## Content

IconButton has no visible text, so its content is the `aria-label` and the
tooltip.

- Name the action, not the icon: 삭제, not 휴지통; 보내기, not 화살표.
- Add the object when the row alone does not make it clear: 멤버 삭제,
  파일 내려받기.
- Use the same word as the tooltip and as any Button for the same action
  elsewhere in the flow.
- Sentence case in English ("Copy link"). No full stop.

## Accessibility

What IconButton does for you:

- It renders a native `<button>`, so Tab reaches it and Enter and Space
  activate it (WCAG 2.1.1).
- A keyboard focus ring (`focus.ring` with a canvas-coloured inner band) on
  `:focus-visible` only (WCAG 2.4.7).
- The resting glyph on `ghost` and `secondary` is `fg.icon`, chosen for 3:1
  against the surface as a non-text graphic (WCAG 1.4.11).
- Disabled is a fixed colour pair, not opacity, and does not react to hover or
  press. `ghost` has no fill to grey out, so its disabled glyph is the lighter
  `disabled.fgGhost` — `disabled.fg` sat too close to the resting `fg.icon`.

What you still have to do:

- **Always pass `aria-label`.** The type does not require it, and without it
  the button has no accessible name (WCAG 4.1.2; axe `button-name`, KWCAG
  5.3.4.1 in ACCESSIBILITY.md §1). Pass it on the first render, not after
  hydration.
- **A tooltip is not the name.** Give the tooltip the same words as the
  `aria-label`, so what a sighted user sees and what a speech-input user says
  match (WCAG 2.5.3).
- **Hide nothing behind colour.** `isDestructive` and `danger` colour the
  glyph; the label (삭제) is what carries the meaning (WCAG 1.4.1).
- **No IconButton inside another control** (ACCESSIBILITY.md §3, axe
  `nested-interactive`). A delete icon on a clickable card goes next to the
  card's link, not inside it.
- **Say why it is disabled.** A disabled send button (nothing typed yet) is
  skipped by Tab; the empty input already explains it. Elsewhere, explain in
  text.

## 문구

IconButton에는 보이는 글자가 없으므로 문구는 `aria-label`과 툴팁입니다.

- 아이콘이 아니라 동작을 적습니다. "휴지통"이 아니라 "삭제", "화살표"가 아니라
  "보내기"입니다.
- 행만 보고는 대상이 분명하지 않다면 대상을 붙입니다: 멤버 삭제, 파일 내려받기.
- 툴팁, 그리고 같은 흐름에서 같은 동작을 하는 Button과 같은 말을 씁니다.
- 영어는 문장형 대소문자를 쓰고("Copy link") 마침표를 찍지 않습니다.

## 접근성

IconButton이 알아서 하는 일

- 기본 `<button>`으로 렌더하므로 Tab으로 이동하고 Enter와 Space로 실행합니다(WCAG
  2.1.1).
- 키보드 초점에만(`:focus-visible`) 초점 링을 그립니다. `focus.ring`에 바탕색 안쪽
  띠를 더한 모양입니다(WCAG 2.4.7).
- `ghost`와 `secondary`의 평소 아이콘 색은 `fg.icon`입니다. 글자가 아닌 그래픽으로서
  바탕과 3:1 대비를 맞춘 값입니다(WCAG 1.4.11).
- 비활성 상태는 투명도가 아니라 고정된 색 한 쌍이며, 마우스를 올리거나 눌러도 변하지
  않습니다. `ghost`는 회색으로 바꿀 바탕이 없어서 비활성 아이콘을 더 옅은
  `disabled.fgGhost`로 칠합니다. `disabled.fg`는 평소 아이콘 색 `fg.icon`과 거의 같아 보였습니다.

직접 챙겨야 하는 일

- **`aria-label`을 반드시 줍니다.** 타입이 강제하지 않으며, 빠뜨리면 버튼에 접근 가능한
  이름이 없습니다(WCAG 4.1.2, axe `button-name`, ACCESSIBILITY.md 1절의 KWCAG
  5.3.4.1). 하이드레이션 이후가 아니라 첫 렌더부터 줍니다.
- **툴팁은 이름이 아닙니다.** 툴팁에 `aria-label`과 같은 말을 넣어, 눈으로 보는 말과
  음성으로 부르는 말이 같게 합니다(WCAG 2.5.3).
- **색에 뜻을 숨기지 않습니다.** `isDestructive`와 `danger`는 아이콘 색만 바꾸고, 뜻은
  "삭제" 같은 라벨이 전합니다(WCAG 1.4.1).
- **컨트롤 안에 IconButton을 넣지 않습니다**(ACCESSIBILITY.md 3절, axe
  `nested-interactive`). 누를 수 있는 카드의 삭제 아이콘은 카드 링크 안이 아니라
  옆에 둡니다.
- **왜 비활성인지 알립니다.** 아직 아무것도 입력하지 않아 비활성인 보내기 버튼은 Tab이
  건너뛰지만, 빈 입력창이 이유를 보여 줍니다. 다른 자리에서는 글로 이유를 적습니다.

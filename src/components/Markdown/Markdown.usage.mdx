# Markdown

Renders a Markdown string with the design system's own components: headings
become `H1`–`H5` (and `h6` a `Subtitle as="h6"`), paragraphs `Text`, links
`Link`, code `InlineCode` or `Code`, tables `Table`. GitHub-flavoured
Markdown, line breaks, highlight markers and KaTeX maths are on.

## When to use

- Long-form text written by someone else or generated: model answers,
  announcements, release notes, help articles.

## When not to use

- A fixed UI string (a label, a toast, an error message) → `Text`. Markdown is
  for content you do not control at build time.
- A chat message with app-specific blocks (citations, tool output) → the
  app's own renderer, passing overrides through `components`.

## Props

| Prop | Means |
| --- | --- |
| `children` | The Markdown string. |
| `components` | Overrides merged over the built-in mapping (`baseMarkdownComponents`, exported). Use it to change heading levels or add custom blocks. |
| `className` | Added to the wrapper next to the built-in spacing styles. |
| Other `react-markdown` options | Passed through. Plugins you pass replace the built-in plugin lists. |

# Markdown

마크다운 글을 이 디자인 시스템의 컴포넌트로 그립니다. 제목은 `H1`–`H5`(`h6`는
`Subtitle as="h6"`), 문단은 `Text`, 링크는 `Link`, 코드는 `InlineCode`나 `Code`, 표는
`Table`이 됩니다. GitHub식 마크다운, 줄바꿈, 형광펜 표시, KaTeX 수식이 켜져 있습니다.

## 언제 쓰나요

- 다른 사람이 썼거나 생성된 긴 글: 모델 답변, 공지, 릴리스 노트, 도움말.

## 언제 쓰지 않나요

- 고정된 화면 문구(라벨, 토스트, 오류 메시지)는 `Text`를 씁니다. Markdown은 빌드할 때
  내용을 알 수 없는 글에 씁니다.
- 인용, 도구 결과처럼 앱 고유의 블록이 있는 채팅 메시지는 앱의 렌더러를 쓰고,
  `components`로 덮어씁니다.

## 속성

| 속성 | 뜻 |
| --- | --- |
| `children` | 마크다운 글. |
| `components` | 기본 매핑(`baseMarkdownComponents`, 내보냄) 위에 덮어쓸 컴포넌트. 제목 수준을 바꾸거나 블록을 추가할 때 씁니다. |
| `className` | 기본 간격 스타일과 함께 바깥 요소에 붙습니다. |
| 그 밖의 `react-markdown` 옵션 | 그대로 넘깁니다. 플러그인을 넘기면 기본 플러그인 목록을 대신합니다. |

## Content

- Write headings in order, starting from the level that fits under the
  page's own heading.
- Write link text that names the destination, and alt text for every image.

## Accessibility

What Markdown does for you:

- Headings stay real headings, including `######` (`as="h6"`), so the
  author's structure reaches the outline (KWCAG 5.2.4.2 제목 제공).
- Tables are real tables, links are underlined `Link`s, and code blocks get
  `Code`'s copy button.

What you still have to do:

- **Fit the heading levels to the page.** `#` becomes an `<h1>`. If the page
  already has an `h1`, map the levels down with `components` (WCAG 1.3.1,
  2.4.6).
- **Images need alt text from the author.** An image written without alt in
  raw HTML gets the placeholder "chat-image", which describes nothing (WCAG
  1.1.1).
- **Links open in a new tab** (`target="_blank"`) with no warning. Say so near
  the content if it matters, or override `a` in `components` (WCAG 3.2.5).
- **Raw HTML is rendered** (`rehype-raw`) and not sanitised. Sanitise
  untrusted input before you pass it in.

## Tokens

The wrapper sets `fg.default`; everything else comes from the components it
maps to.

</En>

## 문구

- 제목은 차례대로 쓰고, 페이지 제목 아래에 맞는 수준에서 시작합니다.
- 링크 문구에는 이동할 곳을 적고, 모든 이미지에 대체 글을 씁니다.

## 접근성

Markdown이 알아서 하는 일

- 제목은 `######`(`as="h6"`)까지 실제 제목으로 남으므로, 작성자가 만든 구조가 문서
  구조에 그대로 들어갑니다(KWCAG 5.2.4.2 제목 제공).
- 표는 실제 표로, 링크는 밑줄이 있는 `Link`로 그려지고, 코드 블록에는 `Code`의 복사
  버튼이 붙습니다.

직접 챙겨야 하는 일

- **제목 수준을 페이지에 맞춥니다.** `#`은 `<h1>`이 됩니다. 페이지에 이미 `h1`이
  있다면 `components`로 수준을 한 단계씩 내립니다(WCAG 1.3.1, 2.4.6).
- **이미지 대체 글은 작성자가 써야 합니다.** HTML로 쓴 이미지에 alt가 없으면 아무것도
  설명하지 않는 "chat-image"가 들어갑니다(WCAG 1.1.1).
- **링크는 안내 없이 새 탭에서 열립니다**(`target="_blank"`). 중요하다면 내용 근처에
  알리거나 `components`에서 `a`를 덮어씁니다(WCAG 3.2.5).
- **HTML이 그대로 그려지고**(`rehype-raw`) 정제되지 않습니다. 믿을 수 없는 입력은
  넘기기 전에 정제합니다.

## 토큰

바깥 요소는 `fg.default`를 쓰고, 나머지는 매핑된 컴포넌트에서 옵니다.

</Ko>

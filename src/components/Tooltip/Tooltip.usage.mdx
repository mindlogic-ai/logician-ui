# Tooltip

A short text label that appears when the pointer rests on, or the keyboard
focuses, the element it describes.

## When to use

- To show the name of an icon-only button: 새로고침, 복사, 공유.
- To show the full text of a label that is cut off, when the element is
  focusable.
- To give the label of a collapsed navigation item.

## When not to use

- Anything the user must read to succeed, such as a password rule or an error →
  visible helper text, `FormControl`, or `Banner`. Touch screens never show a
  tooltip.
- A definition or an explanation with more than one sentence → `InfoSprinkle`.
- Anything clickable, such as a link or a button → `Popover`. The pointer cannot
  reach a tooltip and the keyboard cannot focus inside it.
- A status → `Badge`, `Toast` or `Banner`.

# Tooltip

포인터를 올리거나 키보드 초점이 닿았을 때 그 요소를 설명하는 짧은 라벨입니다.

## 언제 쓰나요

- 아이콘만 있는 버튼의 이름을 보일 때: 새로고침, 복사, 공유.
- 잘린 라벨의 전체 문구를 보일 때. 단, 그 요소가 초점을 받을 수 있어야 합니다.
- 접힌 내비게이션 항목의 이름을 보일 때.

## 언제 쓰지 않나요

- 비밀번호 규칙이나 오류처럼 꼭 읽어야 하는 내용은 눈에 보이는 도움말, `FormControl`,
  `Banner`로 보입니다. 터치 화면에서는 툴팁이 뜨지 않습니다.
- 용어 설명이나 두 문장 이상의 설명은 `InfoSprinkle`을 씁니다.
- 링크나 버튼처럼 누를 수 있는 것은 `Popover`에 넣습니다. 툴팁에는 포인터가 닿지 못하고
  키보드 초점도 들어가지 못합니다.
- 상태는 `Badge`, `Toast`, `Banner`로 알립니다.

## Content

- One to five words for a button name; one short sentence at most. No full
  stop on a name.
- Match the accessible name of the trigger word for word (WCAG 2.5.3).
- Do not repeat visible text. A button that already says "공유" needs no
  tooltip.

## Accessibility

What Tooltip does for you:

- Opens on hover after 300 ms and on keyboard focus; `Escape` closes it, and so
  does scrolling (WCAG 1.4.13).
- While open, the trigger gets `aria-describedby` pointing at the content,
  which has `role="tooltip"` (WCAG 4.1.2).

What you still have to do:

- **Name the trigger yourself.** `aria-describedby` adds a description; it does
  not give an icon-only button a name. Pass `aria-label` on the button.
- **The trigger must be focusable.** Tooltip wraps its child with
  `asChild`, so the child must be a real button, link or other focusable
  element. A disabled button gets no hover or focus, so its tooltip never
  shows.
- Never put the only copy of required information in a tooltip; touch screens
  have no hover.

## 문구

- 버튼 이름은 한 단어에서 다섯 단어, 길어도 짧은 한 문장까지 씁니다. 이름에는 마침표를
  찍지 않습니다.
- 여는 요소의 접근 가능한 이름과 글자 하나까지 같게 씁니다(WCAG 2.5.3).
- 화면에 보이는 문구를 되풀이하지 않습니다. 이미 "공유"라고 쓰인 버튼에는 툴팁이
  필요 없습니다.

## 접근성

Tooltip이 알아서 하는 일

- 포인터를 올리고 300ms가 지나면, 또는 키보드 초점이 닿으면 열립니다. `Escape`를
  누르거나 스크롤하면 닫힙니다(WCAG 1.4.13).
- 열려 있는 동안 여는 요소에 `aria-describedby`가 붙어 `role="tooltip"`인 내용을
  가리킵니다(WCAG 4.1.2).

직접 챙겨야 하는 일

- **여는 요소의 이름은 직접 붙입니다.** `aria-describedby`는 설명을 더할 뿐, 아이콘만
  있는 버튼에 이름을 주지 않습니다. 버튼에 `aria-label`을 넘깁니다.
- **여는 요소가 초점을 받을 수 있어야 합니다.** Tooltip은 자식을 `asChild`로 감싸므로
  자식은 실제 버튼, 링크처럼 초점을 받는 요소여야 합니다. 비활성 버튼은 포인터도 초점도
  받지 않아 툴팁이 뜨지 않습니다.
- 꼭 필요한 정보를 툴팁에만 두지 않습니다. 터치 화면에는 마우스 올리기가 없습니다.

# Menu

A list of actions or choices that opens from a button. Each row does one
thing when chosen.

## When to use

- For the actions on one row or object, behind a "more" button: 이름 변경,
  복제, 삭제.
- For a set of related commands under one button: export as CSV or Excel.
- For picking one setting from a short list in a top bar, such as the display
  language.

## When not to use

- Two or three actions that fit on screen → show them as `Button`s. A menu
  hides them behind an extra click.
- A value in a form → `Select`. A menu does not hold a value or work with a
  label and validation.
- A panel with inputs or checkboxes → `Popover`.
- Switching between views of the same content → `Tabs` or `SegmentedControl`.

# Menu

버튼을 누르면 열리는 동작이나 선택지 목록입니다. 한 줄을 고르면 한 가지 일을 합니다.

## 언제 쓰나요

- 한 줄이나 한 대상에 대한 동작을 "더 보기" 버튼 뒤에 모을 때: 이름 변경, 복제, 삭제.
- 관련된 명령 여러 개를 버튼 하나에 묶을 때: CSV나 Excel로 내보내기.
- 상단 바에서 짧은 목록 중 설정 하나를 고를 때: 표시 언어.

## 언제 쓰지 않나요

- 화면에 들어가는 동작 두세 개는 `Button`으로 그대로 보입니다. 메뉴에 넣으면 한 번 더
  눌러야 합니다.
- 양식의 값은 `Select`로 받습니다. 메뉴는 값을 들고 있지 않고 라벨이나 검증과도 엮이지
  않습니다.
- 입력란이나 체크박스가 있는 패널은 `Popover`를 씁니다.
- 같은 내용의 보기를 바꾸는 것은 `Tabs`나 `SegmentedControl`을 씁니다.

## Content

- Rows start with a verb or are the verb: "이름 변경", "CSV로 내보내기". No full
  stop.
- Order by frequency, with destructive actions last.
- If a row opens a dialog, the label does not need "…"; the dialog's title
  repeats the action.
- Keep one menu under about seven rows. Group longer ones with
  `Menu.ItemGroup` and `Menu.ItemGroupLabel`.

## Accessibility

What Menu does for you:

- The list is `role="menu"`, its rows `role="menuitem"`, and the list is named
  by its trigger. The trigger gets `aria-haspopup`, `aria-expanded` and
  `aria-controls` (WCAG 4.1.2).
- Keyboard (WCAG 2.1.1): `Enter`, `Space` or `↓` opens the menu; `↑` / `↓`
  move between rows, typing a letter jumps to a row, `Enter` chooses, and
  `Escape` closes and returns focus to the trigger.
- The highlighted row is painted the same way for the pointer and the
  keyboard (`primary.wash`, `danger.bg` on a danger row). Focus stays on the
  list and the row is tracked with `aria-activedescendant`, so that fill is
  the visible focus indicator (WCAG 2.4.7).
- A disabled row cannot be chosen and shows a not-allowed cursor.

What you still have to do:

- **Name an icon-only trigger, and include the object.** `aria-label` on the
  `IconButton` inside `Menu.Trigger asChild`: "김민지 님 작업 메뉴", not "메뉴"
  (WCAG 2.4.6).
- **Give row icons `aria-hidden`.** The text is the name.
- **Confirm destructive rows.** `variant="danger"` colours the row; it does not
  ask the user. Open a `Modal`.
- A row that navigates should be a real link: `Menu.Item as={NextLink}
  href=…`, so middle-click and "open in new tab" still work.
- **Tooltip + Menu on one trigger: share `ids.trigger`.** Both make the
  button their trigger and each gives it its own id, so the menu cannot find
  its anchor and opens at the top-left of the page. Pass one `useId()` to
  both: `<Menu ids={{ trigger: id }}><Tooltip ids={{ trigger: id }} …>`.

## 문구

- 줄은 동사로 쓰거나 동사로 시작합니다. "이름 변경", "CSV로 내보내기". 마침표를 찍지
  않습니다.
- 자주 쓰는 순서로 놓고, 되돌릴 수 없는 동작은 맨 아래에 둡니다.
- 대화상자를 여는 줄이라도 "…"를 붙이지 않아도 됩니다. 대화상자 제목이 동작을 다시
  말해 줍니다.
- 메뉴 하나는 일곱 줄 안쪽으로 둡니다. 더 길면 `Menu.ItemGroup`과
  `Menu.ItemGroupLabel`로 묶습니다.

## 접근성

Menu가 알아서 하는 일

- 목록은 `role="menu"`, 줄은 `role="menuitem"`이며, 목록의 이름은 여는 버튼에서
  옵니다. 여는 버튼에는 `aria-haspopup`, `aria-expanded`, `aria-controls`가 붙습니다
  (WCAG 4.1.2).
- 키보드(WCAG 2.1.1): `Enter`, `Space`, `↓`로 열고, `↑`/`↓`로 줄을 옮기고, 글자를
  입력하면 그 글자로 시작하는 줄로 가고, `Enter`로 고르고, `Escape`로 닫으면 초점이 여는
  버튼으로 돌아옵니다.
- 강조된 줄은 포인터든 키보드든 같은 모양(`primary.wash`, 위험 줄은 `danger.bg`)으로
  칠해집니다. 초점은 목록에 머물고 줄은 `aria-activedescendant`로 가리키므로, 이 배경색이
  눈에 보이는 초점 표시입니다(WCAG 2.4.7).
- 비활성 줄은 고를 수 없고, 커서가 금지 모양으로 바뀝니다.

직접 챙겨야 하는 일

- **아이콘만 있는 여는 버튼에 대상까지 담은 이름을 붙입니다.** `Menu.Trigger asChild`
  안의 `IconButton`에 `aria-label`을 줍니다. "메뉴"가 아니라 "김민지 님 작업 메뉴"처럼
  씁니다(WCAG 2.4.6).
- **줄 아이콘에는 `aria-hidden`을 붙입니다.** 이름은 문구가 맡습니다.
- **되돌릴 수 없는 줄은 한 번 더 확인합니다.** `variant="danger"`는 색만 바꿀 뿐 사용자에게
  묻지 않습니다. `Modal`을 엽니다.
- 다른 페이지로 가는 줄은 실제 링크로 만듭니다. `Menu.Item as={NextLink} href=…`로
  쓰면 가운데 클릭과 "새 탭에서 열기"가 그대로 동작합니다.
- **한 버튼에 Tooltip과 Menu를 함께 걸 때는 `ids.trigger`를 같이 씁니다.** 둘 다 그 버튼을
  여는 요소로 삼고 각자 다른 id를 붙이므로, 메뉴가 기준 위치를 못 찾고 화면 왼쪽 위에서
  열립니다. `useId()` 하나를 양쪽에 넘깁니다:
  `<Menu ids={{ trigger: id }}><Tooltip ids={{ trigger: id }} …>`.

# Toast

A short message that confirms the result of something the reader just did,
then goes away on its own.

## When to use

- To confirm an action that has no other visible result: 링크를 복사했습니다,
  설정을 저장했습니다.
- To report that a background action failed or finished, when the reader is
  no longer looking at where it started.
- To offer one follow-up to that result: undo a delete, open the exported file.

## When not to use

- The message must stay until the condition changes → `Banner`.
- An error about one field → the field's error text (`FormControl`). The
  toast disappears; the field is still wrong.
- The reader has to decide before going on → `Modal`.
- Progress of a long job → `ProgressBar`, in the place where the job runs.
- A status attached to one item → `Badge`.

## How it works

- Mount `<Toaster />` once, at the root of the app. Then call
  `const showToast = useToast()` and `showToast({ status, title?, description, action? })`.
  It returns the toast id; `showToast.update(id, options)`,
  `showToast.dismiss(id)` and `showToast.dismissAll()` work on it.
- A toast closes after 5 s, or 8 s when it has an `action`, unless you pass
  `duration`. Hovering or focusing the toasts pauses the timer, and so does
  leaving the browser tab.
- `useToast` keeps at most three of its toasts; a fourth closes the oldest.
- Every toast appears at the top of the window. Placement is set once in
  `Toaster.tsx`, not per toast.
- `useToast()` returns a new function on every render. Do not list it as an
  effect dependency without wrapping it first.

# Toast

사용자가 방금 한 일의 결과를 짧게 확인해 주고, 잠시 뒤 저절로 사라지는 메시지입니다.

## 언제 쓰나요

- 화면에 다른 결과가 보이지 않는 동작을 확인해 줄 때: 링크를 복사했습니다, 설정을
  저장했습니다.
- 백그라운드 작업이 끝나거나 실패했는데, 사용자가 이미 다른 곳을 보고 있을 때.
- 그 결과에 이어서 할 일이 하나 있을 때: 삭제 되돌리기, 내보낸 파일 열기.

## 언제 쓰지 않나요

- 원인이 해결될 때까지 남아 있어야 하는 안내는 `Banner`를 씁니다.
- 입력란 하나의 오류는 그 입력란의 오류 문구(`FormControl`)로 알립니다. 토스트는
  사라지지만 입력란은 여전히 틀린 상태입니다.
- 사용자가 결정해야 다음으로 넘어갈 수 있다면 `Modal`을 씁니다.
- 오래 걸리는 작업의 진행률은 그 작업이 돌아가는 자리에 `ProgressBar`로 보여 줍니다.
- 항목 하나에 붙는 상태는 `Badge`를 씁니다.

## 동작 방식

- 앱 맨 위에 `<Toaster />`를 한 번만 둡니다. 그다음 `const showToast = useToast()`를
  부르고 `showToast({ status, title?, description, action? })`로 띄웁니다. 반환값은
  토스트 id이며, `showToast.update(id, options)`, `showToast.dismiss(id)`,
  `showToast.dismissAll()`에 씁니다.
- `duration`을 넘기지 않으면 5초 뒤에 닫히고, `action`이 있으면 8초 뒤에 닫힙니다.
  토스트 위에 마우스를 올리거나 초점을 옮기면 시간이 멈추고, 브라우저 탭을 떠나도
  멈춥니다.
- `useToast`로 띄운 토스트는 세 개까지 남고, 네 번째가 뜨면 가장 오래된 것이 닫힙니다.
- 토스트는 모두 창 위쪽에 뜹니다. 위치는 `Toaster.tsx`에서 한 번 정하며, 토스트마다
  바꿀 수 없습니다.
- `useToast()`는 렌더할 때마다 새 함수를 돌려줍니다. 감싸지 않은 채 effect 의존성에
  넣지 않습니다.

## Content

- One sentence in `description`, in the past tense for a result:
  "채팅을 삭제했습니다." Add a `title` only when the description needs a
  heading to make sense.
- Say what happened, not what the system is: "크레딧이 부족해 응답을 생성하지
  못했습니다", not "402 Payment Required".
- The action label is a short verb phrase: 되돌리기, 크레딧 구매, 파일 열기.
- Do not put information the reader needs later only in a toast. It will be
  gone.

## Accessibility

What Toast does for you:

- Each toast is `role="status"` inside a polite live region, so screen readers
  read it without moving focus (WCAG 4.1.3).
- `Alt+T` moves focus to the toasts; `Escape` closes the focused toast. The
  action and the × are real buttons (WCAG 2.1.1).
- Hover and focus pause the timer, and the action toast stays longer (8 s), so
  the reader has time to act (WCAG 2.2.1).
- Text, icon, action and × use the status `.fg` colour, which the contrast
  audit checks on `.bg` in both modes (WCAG 1.4.3).

What you still have to do:

- **Errors are announced politely, not as alerts.** If the reader must not miss
  it, also show it on the page (`Banner` with `role="alert"`).
- **The × has no accessible name yet.** The close trigger is a button with only
  an icon (WCAG 4.1.2); a fix belongs in `Toast.tsx`. Until then, do not make
  the × the only way to act on a toast.
- Words, not colour alone (WCAG 1.4.1): the description says it failed; the red
  is a second signal.

## 문구

- `description`에 한 문장을 씁니다. 결과는 과거형으로 씁니다: "채팅을 삭제했습니다."
  `title`은 설명만으로 뜻이 통하지 않을 때만 붙입니다.
- 시스템 상태가 아니라 일어난 일을 씁니다. "402 Payment Required"가 아니라 "크레딧이
  부족해 응답을 생성하지 못했습니다"라고 씁니다.
- 동작 라벨은 짧은 동사구로 씁니다: 되돌리기, 크레딧 구매, 파일 열기.
- 나중에 다시 봐야 하는 정보를 토스트에만 담지 않습니다. 곧 사라집니다.

## 접근성

Toast가 알아서 하는 일

- 토스트마다 `role="status"`가 붙고, 공손한(polite) 라이브 영역 안에 있습니다.
  화면 낭독기는 초점을 옮기지 않고 내용을 읽습니다(WCAG 4.1.3).
- `Alt+T`를 누르면 토스트로 초점이 옮겨지고, `Escape`를 누르면 초점이 있는 토스트가
  닫힙니다. 동작과 ×는 실제 버튼입니다(WCAG 2.1.1).
- 마우스를 올리거나 초점을 두면 시간이 멈추고, 동작이 있는 토스트는 8초 동안 남아서
  읽고 누를 시간이 있습니다(WCAG 2.2.1).
- 글자, 아이콘, 동작, ×는 상태의 `.fg` 색을 씁니다. 이 색은 대비 감사에서 라이트·다크
  모두 `.bg` 위에서 검사합니다(WCAG 1.4.3).

직접 챙겨야 하는 일

- **오류도 공손하게 읽힐 뿐, 경고(alert)로 읽히지 않습니다.** 놓치면 안 되는 오류라면
  페이지에도 보여 줍니다(`role="alert"`를 붙인 `Banner`).
- **×에는 아직 접근 가능한 이름이 없습니다.** 닫기 버튼에 아이콘만 있습니다(WCAG
  4.1.2). 고칠 곳은 `Toast.tsx`입니다. 그 전까지는 ×를 토스트에 대응하는 유일한
  방법으로 만들지 않습니다.
- 색만으로 알리지 않습니다(WCAG 1.4.1). 실패했다는 사실은 문구가 전하고, 빨간색은
  두 번째 신호입니다.

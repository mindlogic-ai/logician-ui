# Component page template

Every component usage page follows the same eight sections, in this order.
**Components/Badge/Usage** is the reference page.

| # | Section | What goes in it | Source |
| --- | --- | --- | --- |
| 1 | **Overview** | One sentence under the title: what the component is for. | New prose |
| 2 | **When to use / when not to** | Each "not" points to the alternative component. | New prose |
| 3 | **Variants and what they mean** | `<ArgTypes of={Stories} include={['variant']} />`, then a table of meaning and examples. | The prop JSDoc, written once |
| 4 | **Do / Don't** | Each specimen is a story, pulled in with `<Canvas of={…} />` and captioned with `<Verdict>`. | New stories |
| 5 | **Content** | Length, case, wording, Korean label rules. | New prose |
| 6 | **Accessibility** | What the component does for you, then what you still have to do. Cite WCAG success criteria; cite a KWCAG item only if `ACCESSIBILITY.md` already uses it. | `ACCESSIBILITY.md` |
| 7 | **Tokens** | The tokens the component reads, light and dark, rendered with `TokenTable` from its `*.styles.ts`. | Generated |
| 8 | **Related** | Neighbouring components and the Foundations page that explains the rule. | New prose |

## How to write one

- Create `src/components/<Name>/<Name>.usage.mdx` and attach it to the stories
  with `<Meta of={Stories} name="Usage" />`.
- Put `<LangToggle />` at the top. Write every block twice, in `<En>` and
  `<Ko>`, in the same file. Leave a blank line inside each tag so Markdown
  parses. For short captions use `<T en="…" ko="…" />`.
- Add each Do/Don't specimen to `<Name>.stories.tsx` with
  `tags: ['!dev']` (hidden from the sidebar) and a name starting with
  `Usage /`. **Never paste JSX into the MDX**: a story type-checks, a code
  block does not.
- Use tokens, not hex, in prose. Swatches come from `TokenTable`, which reads
  the shipped theme.
- Korean copy is written, not translated: complete sentences in 합니다체, no
  한자, no translationese.

The doc helpers (`src/guidelines/_components/`) are not exported from the
library and are excluded from the rollup build.

# 컴포넌트 페이지 템플릿

컴포넌트 사용 페이지는 모두 같은 여덟 절을 같은 순서로 씁니다. 기준 페이지는
**Components/Badge/Usage**입니다.

| # | 절 | 들어갈 내용 | 출처 |
| --- | --- | --- | --- |
| 1 | **개요** | 제목 아래 한 문장. 이 컴포넌트를 어디에 쓰는지 | 새로 작성 |
| 2 | **언제 쓰나요 / 언제 쓰지 않나요** | "쓰지 않는 경우"마다 대신 쓸 컴포넌트를 적습니다 | 새로 작성 |
| 3 | **변형과 뜻** | `<ArgTypes of={Stories} include={['variant']} />` 다음에 뜻과 예를 담은 표 | 속성 JSDoc(한 곳에만 작성) |
| 4 | **이렇게 하세요 / 이렇게 하지 마세요** | 예시마다 스토리를 만들어 `<Canvas of={…} />`로 불러오고 `<Verdict>`로 설명을 답니다 | 새 스토리 |
| 5 | **문구** | 길이, 대소문자, 표현, 한국어 라벨 규칙 | 새로 작성 |
| 6 | **접근성** | 컴포넌트가 알아서 하는 일, 그다음 직접 챙겨야 하는 일. WCAG 성공 기준을 인용하고, KWCAG 항목 번호는 `ACCESSIBILITY.md`에 이미 있는 것만 씁니다 | `ACCESSIBILITY.md` |
| 7 | **토큰** | 컴포넌트가 읽는 토큰의 라이트·다크 값. `*.styles.ts`를 읽어 `TokenTable`로 그립니다 | 자동 생성 |
| 8 | **관련 컴포넌트** | 이웃 컴포넌트와 규칙을 설명하는 Foundations 페이지 | 새로 작성 |

## 작성 순서

- `src/components/<Name>/<Name>.usage.mdx`를 만들고
  `<Meta of={Stories} name="Usage" />`로 스토리에 붙입니다.
- 맨 위에 `<LangToggle />`을 둡니다. 모든 블록을 한 파일 안에서 `<En>`과 `<Ko>`로 두
  번 씁니다. 마크다운이 해석되도록 태그 안쪽에 빈 줄을 둡니다. 짧은 설명은
  `<T en="…" ko="…" />`를 씁니다.
- 이렇게 하세요/하지 마세요 예시는 `<Name>.stories.tsx`에 `tags: ['!dev']`(사이드바에서
  숨김)를 달고 이름을 `Usage /`로 시작해 추가합니다. **MDX에 JSX를 붙여 넣지 않습니다.**
  스토리는 타입 검사를 받지만 코드 블록은 받지 않습니다.
- 본문에는 16진수 값이 아니라 토큰 이름을 씁니다. 색 견본은 실제 테마를 읽는
  `TokenTable`로 그립니다.
- 한국어는 번역하지 말고 처음부터 씁니다. 합니다체의 완전한 문장으로 쓰고, 한자와
  번역투를 쓰지 않습니다.

문서용 도구(`src/guidelines/_components/`)는 라이브러리에서 내보내지 않으며 rollup
빌드에서도 빠집니다.

</Ko>
